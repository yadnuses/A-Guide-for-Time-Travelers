# 给穿越者的指南

欢迎阅读《给穿越者的指南》，这是一本让你无论穿越回过去的任何一个年代，你都能快速根据时事政治积累原始财富，到达人生巅峰的指南。

本指南中的引用与史实完全采用真实史料撰写，所以本文亦可作为研究对应年份历史的趣味科普书。

## 穿越者们，在打开指南之前，请认真阅读以下注意事项：

```
1.每一个年份的指南都在阿拉伯数字命名的对应文件夹内，请根据实际情况找到对应的指南文件
2.指南面向全球范围通用，但通常会把写作重心放在当时的年度地点，但请放心，内容适用于所有大洲
3.指南默认你随身携带一定数量的当地货币作为启动资金（毕竟都有时光机了，我想带点当地货币不成问题），如果实在两手空空，请直接阅读路线卡A-B，这会教你如何赚到第一桶金
4.指南会教会你用先知的视角赚到更多的钱，如在比尔盖茨还在车库创业的时候给他带来第一笔投资，或在早期购买比特币，但因你的决策造成的历史偏差我们无法预估
5.请认真阅读“避坑清单”章节，不遵守里面的内容可能会让你丧命
```

## 合作共建

我们欢迎两种贡献：**补充资料**和**写新的年份**。不管做哪一种，都请先阅读对应的规范。

### 怎么用这份规范

| 你想做什么 | 先读 | 然后照着做 |
|:---|:---|:---|
| 补事实、补机会、给某个年份的指南写新地区适配 | [`docs/data-spec.md`](docs/data-spec.md) | 第 4、5 节的字段表逐项填；`id` 命名看同节的类别缩写表，序号接在该包现有最大值之后 |
| 写某一年、改已有成稿 | [`docs/draft-spec.md`](docs/draft-spec.md) | 第 10 节是写前清单，第 11 节是交付后清单，逐条勾 |
| 拿不准格式 | 直接跑一次校验 | 红灯会指出具体是哪条 ID、哪个字段，照着改就行 |

三步走：

```bash
# 1. 照着规范写完之后，先本地跑一次
python3 research/validate_pack.py 1911 CN

# 2. 看到 OK 再提 PR；带 [提示] 的项不阻断，请在 PR 里说明

# 3. 写年份的话还要过成稿校验
python3 research/check_draft.py 1911
```

**校验脚本就是规范的代码版**：你按规范写，CI 就绿；不按规范写，PR 会被退回。所以最省事的路径是「打开规范 → 照字段填 → 本地跑一次 → 提 PR」，而不是「先写再改」。

### 三种贡献，三种处理

| 类型 | 形式 | 是否自动合并 |
|:---|:---|:---|
| **勘误** | 指出事实错了、来源失效、引文对不上 | 走 Issue |
| **资料层** | 补事实、补机会、开新包、换一手源 | 走pr |
| **成稿层** | 新增或改写年度指南 | **可以在 PR 里写，会经由管理员校对后合并** |

### 五条规则

1. **只追加，不改旧行。** JSONL 新记录写在文件末尾，改动已有行会让 diff 变成整文件，冲突无解。
2. **ID 顺延。** 用该包现有最大序号 +1。两个 PR 撞号时，后合并的一方改号。
3. **一个 PR 只做一件事。** 补一个包、换一批来源、修一处引用，不要混在一起。
4. **不格式化别人的文件。** 不改缩进、字段顺序、标点。
5. **不删来源冲突。** 两个来源打架就并列写、标 `conflicted`，不许为了整齐挑一个。

### 关于镜像源

`wikiwand`、`wiki2` 这类维基镜像站不是禁止项，但来源等级低。全库现有约 17% 的记录引用了镜像源，正在逐步替换。

**新增记录引用镜像源不会红灯，但会在校验输出里被标出来**，PR 里会被问一句"为什么拿不到一手源"。能换就换。

详细的提交步骤、审核标准、常见退回原因，见 [`CONTRIBUTING.md`](CONTRIBUTING.md)。

## 数据拼接方式

每个「年份 / 地区」是一个资料包，三个文件：

```
research/1910/US/
├── facts.jsonl          事实记录，每条带 URL、原文摘录、核验状态
├── opportunities.jsonl  机会记录，标注是「历史已验证」还是「合理推演」
└── summary.md           该包的发现、冲突、缺口与写作建议
```

事实记录的核验状态分三档：`cross_checked`（多源交叉）、`single_source`（单一来源）、`conflicted`（来源互相矛盾，两种口径并列保留，不强行统一）。矛盾不消除，是这套资料的设计原则之一——读者能看见证据本身的分歧。

## 怎么校验

仓库自带脚本，均可从任意目录运行。**每次 PR 会自动跑前两条**，你也可以在本地先跑一遍再提交：

```bash
# 校验资料包结构与字段完整性（无参数则全库）
python3 research/validate_pack.py

# 校验年度初稿：六栏目结构、路线卡五字段、引用连续、附录对应（无参数则扫描全部）
python3 research/check_draft.py

# 年度汇总：各年事实数、机会数、五类核心覆盖
python3 research/summarize_year.py 1900 1910

# 列出引用了维基镜像站/代理站的记录，供替换为一手来源
python3 research/list_mirror_sources.py
```

## 这套东西的前提

以下是写作时自我约束的规则，也是阅读时该带着的怀疑：

- **不虚构价格。** 没有可核验的股票价格、股息、收益率、证券代码，就只写私人股权、合伙、承包、服务入口。
- **不把"后来成功"写成"任何投入都成功"。** 一家公司后来成为巨头，不等于当年任何人买它的股票都能赚钱，也不等于未上市企业当年能被普通穿越者买到。
- **不美化暴力与不义。** 殖民暴力、种族屠杀、政治清洗、法西斯上台，按史实与数字记录，不猎奇、不煽情、不替代读者判断。
- **缺口如实标注。** 资料包里没有的数据，成稿里就写"未取得"，不用常识填补。

## 已知局限

- **年份覆盖不均。** 1900—1910 已成稿并审校；1911—1930 只有资料，没有成稿。
- **地区深度不均。** 每年一个主舞台承载完整故事线，次重点地区篇幅明显更短，机会卡只给一个入口和一条风险。
