# 《给穿越者的指南》数据格式与搜集规范

## 1. 搜集原则

1. 事实与推演分离。可核验事实写入 `facts.jsonl`，生存和赚钱推演写入 `opportunities.jsonl`。
2. 每条事实至少具有一个可靠来源，并保留来源标题、具体链接或书目信息、支持该事实的原文摘录和访问日期。
3. 影响主路线的事件日期、法律状态、价格、金融结果和比赛结果尽量使用第二个独立来源交叉核验。
4. 不允许编造来源、原文摘录、数据或历史结果。无法确认的内容写入 `summary.md` 的资料缺口，不得伪装成事实。
5. subagent 只交付资料和分析，不写年度故事定稿，不修改其他任务的目录。

## 2. 任务单位与目录

第一轮以“年份×国家／地区”为一份任务，第二轮以“年份×全球”为一份任务。

```text
02_资料与考据/
└── YYYY/
    ├── REGION/
    │   ├── facts.jsonl
    │   ├── opportunities.jsonl
    │   └── summary.md
    └── global/
        ├── facts.jsonl
        ├── opportunities.jsonl
        └── summary.md
```

`YYYY` 为四位年份。`REGION` 优先使用 ISO 3166-1 alpha-2 大写国家或地区代码，例如 `FR`、`US`、`GB`；历史政权或无法对应当代代码的地区使用清晰的大写英文名称，例如 `OTTOMAN`。同一项目内必须保持同一代码。

每份任务只写自己的三个文件。全球任务只有在该年份的地区任务完成后才启动。

## 3. 数据种类

| 英文枚举 | 中文名称 | 搜集要求 |
|:---|:---|:---|
| `events` | 事件日历 | 核心固定；重大事件、准确日期和行动时间窗口 |
| `survival_cost` | 生存成本 | 核心固定；货币、物价、工资、食宿和交通 |
| `law_identity` | 法律与身份 | 核心固定；证件、执法、行业准入、法律灰色地带 |
| `finance` | 金融机会 | 核心固定；股票、债券、汇率、黄金、房地产和银行制度 |
| `technology_industry` | 科技与产业 | 核心固定；已有技术、新兴技术、专利和产业风口 |
| `safety_medical` | 安全与医疗 | 按需；战争、灾害、治安、疾病和医疗条件 |
| `business_career` | 商业与职业 | 按需；紧缺技能、就业、贸易和创业机会 |
| `sports_culture` | 体育与文化 | 按需；比赛结果、流行文化、出版和博彩机会 |
| `language` | 语言速查 | 按需；应急表达和当地常用文字 |

## 4. `facts.jsonl` 格式

每行是一个完整 JSON 对象，不添加 Markdown 代码围栏、注释、尾逗号或数组外层。一个对象只陈述一个可独立核验的事实。

```json
{"id":"1900-FR-EVENT-001","year":1900,"region":{"continent":"欧洲","country":"法国","city":"巴黎"},"category":"events","fact":"可独立核验的事实陈述","date":"1900-04-14","sources":[{"title":"来源标题","url":"具体链接或书目信息","quote":"支持该事实的原文摘录","accessed_at":"2026-10-30"}],"verification":"single_source","confidence":"high"}
```

### 必填字段

- `id`：格式为 `YYYY-REGION-类别缩写-三位序号`，全项目唯一。
- `year`：四位整数年份。
- `region`：包含 `continent`、`country`、`city`；全球记录的 `country` 和 `city` 使用 `null`，不适用的 `city` 使用 `null`。
- `category`：使用九类英文枚举之一。
- `fact`：只写事实，不写建议、收益预测或价值判断。
- `date`：使用 `YYYY`、`YYYY-MM`、`YYYY-MM-DD` 或 `开始日期/结束日期`；不适用或无法确认时为 `null`。
- `sources`：至少一项。每项必须包含 `title`、`url`、`quote`、`accessed_at`；纸质书目在 `url` 中写完整书目信息和页码。
- `verification`：`single_source`、`cross_checked` 或 `conflicted`。
- `confidence`：`high`、`medium` 或 `low`，表示证据可靠程度，不表示故事精彩程度。

### 类别缩写

| 类别 | 缩写 |
|:---|:---|
| `events` | `EVENT` |
| `survival_cost` | `COST` |
| `law_identity` | `LAW` |
| `finance` | `FIN` |
| `technology_industry` | `TECH` |
| `safety_medical` | `MED` |
| `business_career` | `BIZ` |
| `sports_culture` | `SPORT` |
| `language` | `LANG` |

## 5. `opportunities.jsonl` 格式

每行是一个完整 JSON 对象。每条机会必须通过 `based_on` 引用至少一个已存在的事实 ID，并标明属于历史已验证路线还是合理推演。

固定栏目《后来者的成功，当下的财富》收录 `history_proven` 类型：某种产品、企业、产业、投资或商业模式后来被真实结果证明成功，穿越者可以尝试在更早时间参与。历史成功不等于当时一定可以买到股票或必然获利，必须核查当时的上市状态、参与渠道、价格、本金、身份和退出窗口。

```json
{"id":"1900-FR-OPP-001","year":1900,"region":{"continent":"欧洲","country":"法国","city":"巴黎"},"title":"机会名称","stage":"first_capital","opportunity_type":"inferred","outcome":null,"outcome_date":null,"hypothesis":"这条路线为什么可能成立","based_on":["1900-FR-EVENT-001"],"time_window":"可行动的时间范围","requirements":["启动所需条件"],"steps":["推演中的行动步骤"],"legal_then":"gray","legal_today":"illegal","risks":["主要风险"],"uncertainties":["尚未证实或需要进一步核查的部分"],"confidence":"medium"}
```

### 字段约束

- `id`：格式为 `YYYY-REGION-OPP-三位序号`，全项目唯一。
- `stage`：`survival`、`first_capital` 或 `wealth_jump`。
- `opportunity_type`：`history_proven` 或 `inferred`。`history_proven` 用于《后来者的成功，当下的财富》，`inferred` 用于尚未被历史结果直接验证的路线。
- `outcome`：后续真实结果。`history_proven` 必须填写具体成功结果，且 `based_on` 至少引用一条证明该结果的事实；`inferred` 必须为 `null`。
- `outcome_date`：后续结果发生的日期或日期范围，格式与事实记录的 `date` 相同；`inferred` 必须为 `null`。
- `hypothesis`：明确说明因果逻辑，不能只写“利用信息差赚钱”。历史已验证路线还需说明后来成功与当前可执行行动之间的关系。
- `based_on`：事实 ID 数组，不得为空；引用的事实必须真实存在。历史结果与当前启动条件可以分别引用不同事实。
- `time_window`：可行动的时间范围；未知时写“未知”，并在 `uncertainties` 说明。
- `requirements`、`steps`、`risks`、`uncertainties`：字符串数组，没有内容时使用空数组；但关键未知条件不得省略。
- `legal_then`、`legal_today`：`legal`、`gray`、`illegal`、`varies` 或 `unknown`。不同现代法域结论不同时使用 `varies`。
- `confidence`：`high`、`medium` 或 `low`，表示路线成立的可信程度，不表示历史结果本身的确定性。

推演允许大胆，但不得删除启动成本、法律风险、市场容量、身份限制和记忆误差等约束。收益数字没有事实依据时不得填写精确金额。公司后来成功不等于当时任意价格买入都能盈利，也不等于该公司当时已经上市。

## 6. `summary.md` 格式

每份摘要按以下顺序组织：

```markdown
# YYYY×REGION 资料摘要

## 任务范围
说明实际覆盖的地区、时间和数据类别。

## 核心发现
列出最重要的事实 ID 及其意义，不复制成长篇正文。

## 主要机会
列出机会 ID、类型、阶段和一句话结论。

## 后来者的成功，当下的财富
单独列出全部 `history_proven` 机会，概述后续真实结果、当时参与渠道及仍然存在的执行限制；没有则写“未形成证据充分的路线”。

## 来源冲突
记录来源之间的矛盾及当前处理依据；没有则写“未发现”。

## 资料缺口
列出未能核实的内容及其对路线的影响；没有则写“未发现”。

## 主舞台建议
说明该地区是否适合作为年度主舞台，并给出理由。
```

## 7. 完成验收

1. 三个文件均存在，JSONL 每行均可被标准 JSON 解析器读取。
2. 五类核心数据均有搜集；确实不存在的类别需在摘要说明搜索过程和证据缺口。
3. 所有事实 ID 和机会 ID 唯一，所有 `based_on` 引用均可解析。
4. 每条机会均具有合法的 `opportunity_type`；`history_proven` 具有具体 `outcome`、`outcome_date` 和证明该结果的事实引用，`inferred` 的两个结果字段均为 `null`。
5. 事实记录不含赚钱建议，推演记录不伪装成已证实事实。
6. 每条事实至少一个完整来源，关键事实标明交叉核验状态。
7. 法律状态、风险和不确定性没有留空规避。
8. 摘要设有《后来者的成功，当下的财富》，如实记录冲突和缺口，不用“资料齐全”代替核验。
